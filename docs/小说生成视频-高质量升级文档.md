# 小说生成视频高质量升级文档

本文档描述 MVP 完成后的升级路线。目标是把“可用的连续性分镜生成工具”升级成“更接近短剧生产流的高质量小说生成视频应用”。

注意：本文档不是 MVP 必做项。只有在 `小说生成视频-MVP实施文档.md` 的流程稳定后再执行。

## 1. 高质量版本目标

MVP 解决的是结构化和基础连续性。

高质量版本要进一步解决：

- 角色视觉更稳定。
- 场景视觉更稳定。
- 镜头之间动作衔接更自然。
- 支持高质量模式：角色图、场景图、首帧、图生视频、尾帧、下一镜头。
- 支持项目级任务进度和恢复。
- 支持最终视频拼接和导出。
- 支持成本控制、失败重试、批量生成。

最终目标流程：

```txt
小说
  ↓
剧情解析
  ↓
角色库 / 场景库
  ↓
角色参考图生成
  ↓
场景参考图生成
  ↓
分镜生成
  ↓
连续性检查与 AI 修正
  ↓
镜头首帧生成
  ↓
图生视频
  ↓
尾帧提取
  ↓
下一镜头首帧继承
  ↓
视频拼接
  ↓
导出成片
```

## 2. 升级阶段总览

建议分 7 个阶段：

```txt
Phase 1  任务系统与项目状态机
Phase 2  角色参考图和场景参考图
Phase 3  首帧生成
Phase 4  图生视频和尾帧继承
Phase 5  AI 连续性修正
Phase 6  视频拼接与导出
Phase 7  生产级体验与成本控制
```

每个阶段都要保持应用可运行，不做长时间不可用的大重构。

## 3. Phase 1：任务系统与项目状态机

把多个长耗时动作变成可恢复任务：

- 生成角色库
- 生成场景库
- 生成分镜
- 生成角色参考图
- 生成场景参考图
- 批量生成镜头视频

## 4. Phase 2：角色参考图和场景参考图

### 4.1 角色参考图

目标：

- 每个主要角色至少有一张稳定参考图。
- 高质量模式推荐生成角色卡。

角色参考图类型：

```ts
export interface CharacterReferenceImages {
  portrait?: string;
  fullBody?: string;
  turnaround?: string;
  expressionSheet?: string;
  uploaded?: string[];
}
```

数据库可以继续使用 `story_characters.referenceImagesJson`。

### 4.2 角色图生成策略

优先级：

1. 用户上传图。
2. AI 生成 portrait / fullBody。
3. AI 生成 turnaround。

推荐先支持：

- `portrait`
- `fullBody`

暂缓：

- 三视图自动拆分。
- 表情表。

角色图 prompt：

```txt
专业影视角色设定图。

角色固定设定：
{identityPrompt}

画面要求：
- 单个角色
- 纯色浅灰背景
- 全身站姿
- 正面视角
- 同一张脸
- 同一套服装
- 同一发型
- 同一配饰
- 高清，细节清楚
- 不要背景场景

负面约束：
{negativePrompt}
多个人物，换脸，换衣服，复杂背景，文字，水印
```

### 4.3 场景参考图

场景参考图类型：

```ts
export interface LocationReferenceImages {
  establishing?: string;
  angleA?: string;
  angleB?: string;
  uploaded?: string[];
}
```

场景图 prompt：

```txt
影视场景概念设定图。

场景固定设定：
{scenePrompt}

画面要求：
- 无人物
- 展示完整空间结构
- 保持建筑、色彩、光线、主要道具
- 作为后续视频生成的场景参考
- 高清，干净，空间关系明确

负面约束：
{negativePrompt}
人物，时代错误，光线突变，建筑变化，模糊，文字，水印
```

## 6. Phase 4：图生视频和尾帧继承

### 6.1 目标

高质量模式中不再直接文生视频，而是：

```txt
startFrame + shot videoPrompt → 图生视频
```

后续镜头：

```txt
shot N endFrame → shot N+1 startFrame
```

### 6.2 图生视频模型

优先使用已有模型配置里的：

- `happyhorse-1.0-i2v`
- 或百炼文档中可用的图生视频模型。

要求：

- `generateShotVideo` 增加 `mode`：

```ts
type ShotGenerationMode = "fast_t2v" | "reference_r2v" | "quality_i2v";
```

策略：

- `fast_t2v`：无参考图，文生视频。
- `reference_r2v`：角色/场景参考图，参考生视频。
- `quality_i2v`：首帧图，图生视频。

### 6.3 尾帧提取

引入 `ffmpeg`。

需要确认本地是否有 `ffmpeg`。如果没有：

- 文档提示安装。
- 或使用 npm 包封装，但仍依赖二进制。

新增：

```txt
apps/server/src/lib/video.ts
```

接口：

```ts
export async function extractLastFrame(inputVideoPath: string, outputImagePath: string): Promise<void>;
export async function extractFirstFrame(inputVideoPath: string, outputImagePath: string): Promise<void>;
```

尾帧提取时机：

- 视频下载本地成功后。
- 如果 shot 是高质量模式，则提取最后一帧，写入 `endFrameUrl`。

### 6.4 下一镜头继承

规则：

- 如果 shot N 和 shot N+1 在同一场景，并且剧情连续，shot N+1 的 startFrame 默认使用 shot N 的 endFrame。
- 如果换场景，重新生成 startFrame。
- 用户可以手动解除继承。

数据库新增：

```ts
inheritsStartFrameFromShotId: integer("inherits_start_frame_from_shot_id"),
```

前端显示：

- “继承上一镜头尾帧”开关。
- 如果继承，显示来源 shot。

## 7. Phase 5：AI 连续性修正

### 7.1 目标

MVP 只检查并让用户手动修。升级版增加 AI 修正：

```txt
分镜
  ↓
规则检查
  ↓
issues
  ↓
AI 修正分镜
  ↓
再次规则检查
```

### 7.2 API

```txt
POST /api/novel-video/projects/:id/continuity/fix
```

### 7.3 修正规则

AI 只能修改：

- `actionStart`
- `actionEnd`
- `emotionStart`
- `emotionEnd`
- `characterFacing`
- `camera.angle`
- `camera.movement`
- 少量 `narrative` 描述

AI 不能修改：

- 剧情核心事件。
- 角色列表。
- 场景列表。
- 已锁定角色 profile。
- 已锁定场景 profile。
- 已完成视频的 shot，除非用户勾选允许重写。

### 7.4 Prompt

```txt
你是影视连续性监督。

下面是一组结构化分镜，以及连续性检查器发现的问题。

请修正分镜，使动作、情绪、人物朝向、镜头轴线更连续。

硬性规则：
1. 不改变剧情主线。
2. 不新增角色。
3. 不新增场景。
4. 不修改 locked 的角色和场景设定。
5. 不修改已经 completed 且未允许重写的镜头。
6. 输出完整 JSON 数组。

分镜：
{shots}

问题：
{issues}

角色库：
{characters}

场景库：
{locations}
```

## 8. Phase 6：视频拼接与导出

### 8.1 目标

把多个 shot 视频按顺序拼接为一个成片。

### 8.2 数据库

`story_projects` 新增：

```ts
finalVideoUrl: text("final_video_url"),
```

或新增表：

```ts
export const projectExports = sqliteTable("project_exports", {
  id: integer("id").primaryKey({ autoIncrement: true }),
  projectId: integer("project_id").notNull().references(() => storyProjects.id),
  status: text("status").notNull().default("pending"),
  videoUrl: text("video_url"),
  errorMessage: text("error_message"),
  createdAt: integer("created_at").notNull().$defaultFn(() => Date.now()),
  updatedAt: integer("updated_at").notNull().$defaultFn(() => Date.now()),
});
```

推荐用 `project_exports`，方便多次导出。

### 8.3 拼接实现

新增：

```txt
apps/server/src/lib/ffmpeg.ts
```

流程：

1. 确认所有需要导出的 shot 都有本地视频。
2. 转码为统一格式：
   - mp4
   - h264
   - yuv420p
   - 相同分辨率
   - 相同帧率
3. 使用 concat 拼接。
4. 输出到 `uploads/projects/{projectId}/exports/{exportId}.mp4`。
5. 返回 `/api/uploads/...` URL。

### 8.4 API

```txt
POST /api/novel-video/projects/:id/export
GET  /api/novel-video/projects/:id/exports
```

### 8.5 前端

生成页增加：

- “导出成片”按钮。

- 下载按钮。

## 9. Phase 7：生产级体验与成本控制

### 9.1 成本预估

在生成前估算：

- 角色参考图成本。
- 场景参考图成本。
- 首帧图成本。
- 每个 shot 视频成本。
- 总成本。

新增 API：

```txt

```

### 9.2 批量生成控制

功能：

- 选择镜头范围。
- 只生成失败镜头。
- 只生成未完成镜头。
- 并发数设置，默认 1。
- 每次生成前确认预计成本。

新增：


触发版本：

- 用户修改 shot。

- 重建 prompt。
- 重新生成视频。

### 9.4 用户体验

需要增加：

- 项目保存状态。
- 自动刷新但不打断编辑。
- 编辑冲突提示。
- 失败镜头聚合列表。
- 一键重试失败镜头。

## 11. 高质量验收标准

达到高质量版本时，应满足：

- 每个主要角色都有参考图。
- 每个核心场景都有参考图。
- 每个 shot 至少有 videoPrompt。
- 高质量模式下，每个 shot 有 startFrame。
- 同场景连续镜头可以继承上一镜头 endFrame。
- 视频生成结果可以提取 endFrame。
- 项目可以导出最终 mp4。
- 任务可以失败重试。
- 成本可预估。
- 用户能明确知道哪一步失败、为什么失败、如何重试。

## 12. 推荐执行顺序

不要一次做完。按下面顺序：

1. 项目 job 表和 job runner。
2. 角色参考图生成。
3. 场景参考图生成。
4. shot startFrame 字段和首帧生成。
5. `quality_i2v` 图生视频模式。
6. ffmpeg 尾帧提取。
7. 下一镜头继承尾帧。
8. AI 连续性修正。
9. 视频拼接导出。
10. 成本预估和批量生成。
11. shot 版本管理。
12. UI 体验打磨。

## 13. 风险和取舍

### 13.1 百炼模型能力限制

不同模型对参考图、首帧、尾帧的支持不同。实现前必须对照 `docs/bailian` 中的模型文档，确认参数格式。

### 13.2 尾帧不是模型直接返回

尾帧大概率需要本地从视频中提取。需要 `ffmpeg`。

### 13.3 成本上升

高质量模式会显著增加成本：

- 角色图
- 场景图
- 首帧图
- 图生视频
- 重试

所以必须加入成本预估和用户确认。

### 13.4 一致性不能完全保证

连续性引擎只能提高一致性，不能 100% 保证模型输出稳定。因此需要：

- 锁定机制。
- 参考图。
- 首帧继承。
- 失败重试。
- 用户可编辑。
