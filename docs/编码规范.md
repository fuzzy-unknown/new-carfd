# 编码规范

## 项目结构

- **apps/** — 应用入口（server、web 等）
- **packages/** — 可复用的共享包（shared 等）
- **scripts/** — 根级开发脚本（dev、kill-port 等）

不使用 `bun --filter`，子项目命令统一使用 `bun run --cwd <path> <script>`。

## 架构原则

### 单一职责

一个文件、一个模块、一个函数只承担一个清晰职责。

**分层边界（不可混写）：**

| 层         | 职责                           | 示例                        |
| ---------- | ------------------------------ | --------------------------- |
| HTTP       | 请求/响应、路由、参数校验      | `routes/*.ts`               |
| 业务       | 业务逻辑编排                   | `services/*.ts`（未来按需） |
| Repository | 数据库读写                     | `db/*-repository.ts`        |
| Provider   | 外部服务调用                   | `providers/*.ts`（未来按需）|
| Worker     | 异步任务、定时任务             | `workers/*.ts`（未来按需）  |
| UI 状态    | 前端状态管理、hooks            | `hooks/*.ts`、`stores/*.ts` |

### 类型优先

- 生产代码禁止使用 `any` 和 `as any`。
- 确实需要解析未知输入时，必须放在 parser / type guard 边界。
- 导出类型供跨包使用：`schema.ts` 中通过 `inferSelectModel` / `inferInsertModel` 导出。

### 可测试优先

- 每个核心行为都要能通过小范围测试验证。
- Repository 函数接受 `db` 实例参数（或通过模块作用域注入），不隐式依赖全局状态。
- HTTP 层可独立测试路由映射，不依赖数据库。

### 不做隐式兼容

- 不为单体前端、临时 hash 路由或未规划 API 前缀新增兼容代码。
- 不添加未被当前需求使用的抽象层或配置项。

## 端口约定

| 服务   | 端口 |
| ------ | ---- |
| Web    | 5179 |
| Server | 3000 |

启动前必须先关闭占用端口的进程（`scripts/kill-port.ts`）。

## 代码风格

- 使用 `const` 声明不会重新赋值的变量。
- 导出的组件使用命名导出（`export function` / `export const`），不用默认导出。
- 配置常量使用 `as const` 断言。
- 不写无用注释。注释只解释 **Why**，不解释 **What**。

## 依赖管理

- 使用 Bun workspace 管理依赖。
- workspace 内部引用使用 `workspace:*` 协议。
- 不安装未使用的依赖。
